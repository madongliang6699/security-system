软件包（rocketmq-all-4.7.1-bin-release.zip）在阿里云盘。
===============================================================================================


1、把这里的rocketmq-all-4.7.1-bin-release.zip安装包放到Linux服务器的/appp/service目录下

2、解压到/appp/service下  ：unzip -o -d /app/service rocketmq-all-4.7.1-bin-release.zip

3、调整启动内存：

调整nameserver启动的内存（如果服务器内存比较大，可以不调整），如果内存较小，不调整此文件，可能导致无法启动：
修改 bin目录下的 runserver.sh中的这一行：
JAVA_OPT="${JAVA_OPT} -server -Xms256m -Xmx512m -Xmn512m -XX:MetaspaceSize=256m -XX:MaxMetaspaceSize=320m"

调整broker的启动内存：
修改bin目录下的runbroker.sh的这一行：
JAVA_OPT="${JAVA_OPT} -server -Xms256m -Xmx512m -Xmn256m"



4、调整日志文件打印位置（不修改也行，知道位置在当前用户目录下就行）：

# vim conf/logback_broker.xml
# vim conf/logback_filtersrv.xml
# vim conf/logback_namesrv.xml
# vim conf/logback_tools.xml
以上四个日志配置文件里面，将类似于 [${user.home}/logs/rocketmqlogs/namesrv_default.log] 修改为自定义的日志路径，如[/data/logs/rocketmqlogs/namesrv_default.log],如果不修改，日志就会写入到用户目录下的logs目录下。



5、启动rocketmq

cd到/app/service/rocketmq-all-4.7.1-bin-release目录：

启动namesrv服务：nohup sh bin/mqnamesrv &
【mqnamesrv内部回去执行上面的runserver.sh】

然后看输出信息：
# tail -f nohup.out
The Name Server boot success　　#输出此类信息，说明启动成功



再启动broker服务，启动broker之前，为了避免broker使用系统内网ip或者docker虚拟ip，需要给broker指定namesrv的ip和broker自身的ip：
在conf下的broker.conf中最下面添加两行：
--------------------------------------------------------
brokerClusterName = DefaultCluster
brokerName = broker-a
brokerId = 0
deleteWhen = 04
fileReservedTime = 48
brokerRole = ASYNC_MASTER
flushDiskType = ASYNC_FLUSH

# 下面两行是添加的
# 这里指定namesrv的地址
namesrvAddr=127.0.0.1:9876
# 配置broker的地址，是大写的IP一定要注意！！！修改成自己的IP地址
brokerIP1=124.222.246.77

# Broker 对外服务的监听端口，可以不添加这个，默认就是10911
listenPort=10911
------------------------------------------------------------

阿里云或腾讯云不要忘记开安全组端口：namesrvAddr的9876端口和broker的10911端口
我们在安装rocketmq后，要开放的端口一般有4个：9876、10909、10911、10912，端口的用处看最下面。

启动broker：nohup sh bin/mqbroker -c conf/broker.conf &
【mqbroker内部回去执行上面的runbroker.sh】

# tail -f nohup.out
The broker[broker-a, 124.222.246.77:10911] boot success. serializeType=JSON and name server is localhost:9876


6、查看日志
查看日志：tail -f ~/logs/rocketmqlogs/namesrv.log
查看日志：tail -f ~/logs/rocketmqlogs/broker.log


7. rocketmq服务关闭
关闭namesrv服务：sh bin/mqshutdown namesrv
关闭broker服务 ：sh bin/mqshutdown broker

启动服务时提示以下异常信息：

Java HotSpot(TM) 64-Bit Server VM warning: UseCMSCompactAtFullCollection is deprecated and will likely be removed in a future release.
Java HotSpot(TM) 64-Bit Server VM warning: INFO: os::commit_memory(0x00000006c0000000, 2147483648, 0) failed; error='Cannot allocate memory' (errno=12)
#
# There is insufficient memory for the Java Runtime Environment to continue.

问题分析：
根据日志信息分析可以得出是内存不足导致的，需要分别对 bin/runserver.sh 和 bin/runbroker.sh 中内存配置简单做调整。


异常2：
启动服务时提示以下异常信息：
ERROR Disk Check Scheduled Thread 1-Error when measuring diskspace usage， file doesnt exist on this path：
/root/store/commitlog
问题分析：
路径不存在。
解决方法：
创建 /root/store/commitlog 目录，并重启服务。


以下总结来着网络：
9876、10909、10911、10912，端口的用处：
9876这个是nameserver中的端口,不做过多解释，链接nameserver就靠这个端口。
剩下的3个都是RocketMQ-Broker中的端口：
10911：listenPort参数是broker的监听端口号，是remotingServer服务组件使用，作为对Producer和Consumer提供服务的端口号，默认为10911，可以通过配置文件修改，打开broker-x.conf，修改或增加listenPort参数 listenPort=10911 。
10909：fastListenPort参数是fastRemotingServer服务组件使用，默认为listenPort - 2，可以通过配置文件修改，打开broker-x.conf，修改或增加fastListenPort参数 listenPort=10909 。
【注意：rocketMQ的界面化控制台rocketmq-dashboard就是使用10909的，所以这个端口还是要开放的。我们的应用程序集成的rocketMQ客户端使用的是10911】
10912：haListenPort参数是HAService服务组件使用，用于Broker的主从同步，默认为listenPort - 1，可以通过配置文件修改，haListenPort=10912。


remotingServer和fastRemotingServer的区别：

Broker端：
remotingServer可以处理客户端所有请求，如：生产者发送消息的请求，消费者拉取消息的请求。
fastRemotingServer功能基本与remotingServer相同，唯一不同的是不可以处理消费者拉取消息的请求。
Broker在向NameServer注册时，只会上报remotingServer监听的listenPort端口。

客户端：
默认情况下，生产者发送消息是请求fastRemotingServer，我们也可以通过配置让其请求remotingServer；消费者拉取消息只能请求remotingServer。
