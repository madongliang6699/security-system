seata架构下的事务管理中，有三个重要的角色：

TC：transaction coordinate。事务协调者：维护全局和分支事务的状态，协调全局事务提交和回滚。
TM：transaction manager。事务管理者：定义全局事务范围，开始全局事务，提交和回滚全局事务。
RM：resource manager。资源管理器。管理分支事务的资源，与TC交谈以注册分支事务和报告分支事务的状态，并驱动分支事务提交和回滚。

其中TC这个事务协调者，是一个独立的服务，我们使用seata要安装的seata服务，就是TC，或叫TC服务。
TM和RM是seata jar包中的随项目启动后运行的程序逻辑，是对我们业务方法的一个代理和管理。




安装TC服务：

1、把当前包里的zip包放到Linux服务器解压到 /app/service: unzip -o -d /app/service seata-server-1.3.0.zip

2、修改/app/service/seata-1.3.0/conf中的 registry.conf 文件，修改成：
==============================================================================
# seata的这个配置文件主要分两个部分，第一个是registry部分，用来指定使用什么注册中心，seata和其他业务服务一样，也是注册到注册中心的。
# 第二个部分是config部分，用来指定配置中心，之前学习springCloud的时候也有一个远程的统一的配置中心，这个是一样的道理，用来指定远程的统一的配置中心的。


# 第一部分，指定注册中心
registry {
  # file 、nacos 、eureka、redis、zk、consul、etcd3、sofa。 【注册中心的类型，这里选择nacos。】
  type = "nacos"

  nacos {
    application = "seata-server"
    serverAddr = "124.222.246.77:8848"
    # group = "SEATA_GROUP"  【在nacos中，我们的业务服务都在DEFAULT_GROUP这个组里，这里也改成DEFAULT_GROUP】
    group = "DEFAULT_GROUP"
	# 这个命名空间我们使用的是dev
    namespace = "a9b8e131-eedd-40f8-9bdf-5f778779a271"
    cluster = "default"
	# 下面两个是要注册的nacos的账户密码，使用的还是默认的nacos
    username = "nacos"
    password = "nacos"
  }

}


# 第二部分，指定配置中心
config {
  # file、nacos 、apollo、zk、consul、etcd3 【这里也选择nacos，一般真正做微服务的话，尽量还是使用统一的配置中心，而不是在本地file中。默认是file】
  type = "nacos"

  nacos {
    serverAddr = "124.222.246.77:8848"
    namespace = "a9b8e131-eedd-40f8-9bdf-5f778779a271"
    group = "DEFAULT_GROUP"
    username = "nacos"
    password = "nacos"
	# 这个是配置文件的名字，也就是从远程nacos拉配置信息的文件，nacos的”配置列表“中应该有这样一个文件，需要手动添加。
	dataId = "seataServer.properties"
  }

}
===============================================================================================

4、在数据库中创建上面要使用到的seata数据库和表：

建表语句：
=====================================================================
CREATE TABLE IF NOT EXISTS `global_table`
(
    `xid`                       VARCHAR(128) NOT NULL,
    `transaction_id`            BIGINT,
    `status`                    TINYINT      NOT NULL,
    `application_id`            VARCHAR(32),
    `transaction_service_group` VARCHAR(32),
    `transaction_name`          VARCHAR(128),
    `timeout`                   INT,
    `begin_time`                BIGINT,
    `application_data`          VARCHAR(2000),
    `gmt_create`                DATETIME,
    `gmt_modified`              DATETIME,
    PRIMARY KEY (`xid`),
    KEY `idx_status_gmt_modified` (`status` , `gmt_modified`),
    KEY `idx_transaction_id` (`transaction_id`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4;

-- the table to store BranchSession data
CREATE TABLE IF NOT EXISTS `branch_table`
(
    `branch_id`         BIGINT       NOT NULL,
    `xid`               VARCHAR(128) NOT NULL,
    `transaction_id`    BIGINT,
    `resource_group_id` VARCHAR(32),
    `resource_id`       VARCHAR(256),
    `branch_type`       VARCHAR(8),
    `status`            TINYINT,
    `client_id`         VARCHAR(64),
    `application_data`  VARCHAR(2000),
    `gmt_create`        DATETIME(6),
    `gmt_modified`      DATETIME(6),
    PRIMARY KEY (`branch_id`),
    KEY `idx_xid` (`xid`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4;

-- the table to store lock data
CREATE TABLE IF NOT EXISTS `lock_table`
(
    `row_key`        VARCHAR(128) NOT NULL,
    `xid`            VARCHAR(128),
    `transaction_id` BIGINT,
    `branch_id`      BIGINT       NOT NULL,
    `resource_id`    VARCHAR(256),
    `table_name`     VARCHAR(32),
    `pk`             VARCHAR(36),
    `status`         TINYINT      NOT NULL DEFAULT '0' COMMENT '0:locked ,1:rollbacking',
    `gmt_create`     DATETIME,
    `gmt_modified`   DATETIME,
    PRIMARY KEY (`row_key`),
    KEY `idx_status` (`status`),
    KEY `idx_branch_id` (`branch_id`),
    KEY `idx_xid_and_branch_id` (`xid` , `branch_id`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4;

CREATE TABLE IF NOT EXISTS `distributed_lock`
(
    `lock_key`       CHAR(20) NOT NULL,
    `lock_value`     VARCHAR(20) NOT NULL,
    `expire`         BIGINT,
    primary key (`lock_key`)
) ENGINE = InnoDB
  DEFAULT CHARSET = utf8mb4;

5、启动TC服务

先修改 bin/seata-server.sh 中的启动内存，修改成128m：
exec "$JAVACMD" $JAVA_OPTS -server -Xmx128m -Xms128m -Xmn128m -Xss512k -XX:SurvivorRatio=10 -XX:MetaspaceSize=128m -XX:MaxMetaspaceSize=128m -XX:MaxDirectMemorySize=128m -XX:-OmitStackTraceInFastThrow -XX:-UseAdaptiveSizePolicy -XX:+HeapDumpOnOutOfMemoryError -XX:HeapDumpPath="$BASEDIR"/logs/java_heapdump.hprof -XX:+DisableExplicitGC -XX:+CMSParallelRemarkEnabled -XX:+UseCMSInitiatingOccupancyOnly -XX:CMSInitiatingOccupancyFraction=75 -Xloggc:"$BASEDIR"/logs/seata_gc.log -verbose:gc -Dio.netty.leakDetectionLevel=advanced \

启动：
nohup sh bin/seata-server.sh -h 124.222.246.77 &
【启动seata尽量加上指定IP的参数，要不然注册到nacos上的seata服务的ip可能是内网的ip，或者docker容器的ip】

【怎么关闭seata？ 目前是使用kill杀进程的方式关闭seata服务的】

nohup.out文件中最后有：Server started, listen port: 8091  就说明启动成功。
【这样启动的不知道是集群模式还是单例模式】


然后查看nacos的服务列表中会有seata-server服务。
