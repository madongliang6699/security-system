----------------------------------------------------------------------------------- Bean Aware接口回调： 这个没看懂是要干嘛的，这里先不总结。 ----------------------------------------------------------------------------------- Bean初始化前操作 这个阶段的源码： @Override public Object applyBeanPostProcessorsBeforeInitialization(Object existingBean, String beanName) throws BeansException { Object result = existingBean;//当前正在要初始化的bean for (BeanPostProcessor processor : getBeanPostProcessors()) { Object current = processor.postProcessBeforeInitialization(result, beanName); if (current == null) { return result; } result = current; } return result; } 会调用BeanPostProcessor接口的postProcessBeforeInitialization方法，若返回null，当前方法将结束。 通常称postProcessBeforeInitialization这个方法为：bean初始化前操作。 【疑问：是实现了这个接口的bean的在初始化前执行这个操作，还是所有的bean在初始化前都执行这个操作。（经过测试，是对所有bean都执行。）】 【也就是说，spring在启动后会在适当的时候（应该是所有bean的初始化之前）执行上面这个applyBeanPostProcessorsBeforeInitialization方法，看这个方法内部的核心逻辑就是执行BeanPostProcessor接口的 postProcessBeforeInitialization方法 ，这个方法可以对当前的bean做初始化之前的定制化处理，所以如果我们想要在每个bean的初始化之前有针对性的做什么事的话， 就写一个类实现BeanPostProcessor接口的postProcessBeforeInitialization方法，在方法内部通过条件判断当前bean是否符合自己预定的标记（比如这个bean有没有方法标注了自己的特定注解）， 如果符合条件就对这个bean做一些事情，达到bean初始化前对其就行特殊处理的目的。】 基于上面的原理，spring已经为BeanPostProcessor接口做了2个内置的实现类，比较重要，这两个类也是我们使用BeanPostProcessor的一个很好的案例， 我们平时写代码可以利用上这两个实现类已经为我们实现的功能： 第一个：org.springframework.context.support.ApplicationContextAwareProcessor 第二个：org.springframework.context.annotation.CommonAnnotationBeanPostProcessor 第一个详解： ApplicationContextAwareProcessor实现了BeanPostProcessor的postProcessBeforeInitialization方法，在这个方法中，ApplicationContextAwareProcessor为我们 注入6个Aware接口对象，前提是如果bean实现了下面的接口，在ApplicationContextAwareProcessor#postProcessBeforeInitialization中会依次调用下面接口中的方法，将Aware前缀对应的对象注入到bean实例中。 EnvironmentAware：注入Environment对象 EmbeddedValueResolverAware：注入EmbeddedValueResolver对象 ResourceLoaderAware：注入ResourceLoader对象 ApplicationEventPublisherAware：注入ApplicationEventPublisher对象 MessageSourceAware：注入MessageSource对象 ApplicationContextAware：注入ApplicationContext对象 从名称上可以看出这个类以ApplicationContext开头的，说明这个类只能在ApplicationContext环境中使用。 来个案例，感受一下：demo9的PostProcessBeforeInitializationTest1案例 第二个详解： CommonAnnotationBeanPostProcessor实现了每个bean初始化之前都会调用@PostConstruct标注的方法： CommonAnnotationBeanPostProcessor也是通过实现BeanPostProcessor#postProcessBeforeInitialization方法（可以去研究一下这个方法的源码）， 在方法中会通过一些判断，当当前bean中有@PostConstruct注解的方法时，会调用当前bean中所有标注@PostConstruct注解的方法。 @PostConstruct通常用来做初始化的预先缓存一些数据到项目里。 【网上的一段话：通常我们会是在Spring框架中使用到@PostConstruct注解。从依赖注入的字面意思就可以知道，要将对象b注入到对象a， 那么首先就必须得生成对象a和对象b，才能执行注入。所以，如果一个类A中有个成员变量b被@Autowried注解， 那么@Autowired注入是发生在A的构造方法执行完之后的。如果想在生成对象时完成某些初始化操作，而偏偏这些初始化操作又依赖于依赖注入， 那么久无法在构造函数中实现。为此，可以使用@PostConstruct注解一个方法来完成初始化，@PostConstruct注解的方法将会在依赖注入完成后被自动调用。 作者：miraclewu 链接：https://juejin.cn/post/6844904158122737672 来源：稀土掘金 著作权归作者所有。商业转载请联系作者获得授权，非商业转载请注明出处。】 ----------------------------------------------------------------------------------------------------- Bean初始化阶段 2个步骤： 第一：调用InitializingBean接口的afterPropertiesSet方法 第二：调用定义bean的时候指定的初始化方法。 详解： 第一：调用InitializingBean接口的afterPropertiesSet方法 public interface InitializingBean { void afterPropertiesSet() throws Exception; } 当我们的bean实现了这个接口的时候，会在这个阶段被调用。 第二：调用bean定义的时候指定的初始化方法: 先来看一下如何指定bean的初始化方法，3种方式 方式1：xml方式指定初始化方法: < bean init-method="bean中方法名称"/> 方式2：@Bean的方式指定初始化方法: @Bean(initMethod = "初始化的方法") 方式3：api的方式指定初始化方法 this.beanDefinition.setInitMethodName(methodName); 初始化方法最终会赋值给下面这个字段： org.springframework.beans.factory.support.AbstractBeanDefinition#initMethodName 案例：demo9：InitMethodTest -------------------------------------------------------------------------------------------------------------- Bean初始化后阶段 这块的源码： @Override public Object applyBeanPostProcessorsAfterInitialization(Object existingBean, String beanName) throws BeansException { Object result = existingBean; for (BeanPostProcessor processor : getBeanPostProcessors()) { Object current = processor.postProcessAfterInitialization(result, beanName); if (current == null) { return result; } result = current; } return result; } 调用BeanPostProcessor接口的postProcessAfterInitialization方法，返回null的时候，会中断上面的操作。 通常称postProcessAfterInitialization这个方法为：bean初始化后置操作。 【原理和上面的初始化前的操作一样。】 案例：demo9：PostProcessAfterInitializationTest
