springSecurity 是由很多过滤器组成的，每个过滤器又有不同的作用：
其中有的过滤器是用于认证的，有的过滤器是使用与授权的，有的过滤器是实现了一个默认的登录页和退出页等。

其中默认的认证的过滤器内部默认就使用了一个账户密码，只要引入springSecurity就默认必须使用这个用户密码登录，才能继续访问。
也就是默认就给我们所有的请求做了拦截保护。

但是这个默认的用户名密码不是我们自己的业务用户，我们要想使用我们数据库中的用户名和密码就需要
知道他内部是使用了哪个接口或抽象类下的实现类取获取用户名和密码的，知道了这个接口或抽象父类之后就可以自己写一个实现类替换掉默认的实现，
替换成我们自己的类取数据库查询用户和密码。
替换之后就不会使用springSecurity内部默认的用户名和密码了。
（默认的用户名是“user”，密码是通过UUID随机生成的打印在控制台。通过看源码也可以知道，其实也可以用配置文件先配置好这个默认用户名密码，默认如果配置文件中没有的话
才使用”user“和UUID。
这样配置：
spring.security.user.name=root
spring.security.user.password=root
spring.security.user.roles=admin,users
）

其实springSecurity给我们已经设置后的默认实现有很多，比如默认的拦截请求的规则（比如静态资源要不要拦截，哪些特定接口可以放行），默认的密码加密规则等，
都有默认实现，但是我们如果想要自己修改这些实现规则，就需要自己写一些配置类，配置类里面可以注册一些实现类去替换掉上面的那个默认实现，进而达到我们想要的效果。

所以，本文件夹总结的代码，是基于老师的笔记，写的一些自定义实现类或自定义配置，达到使用springSecurity实现业务需求的实战代码。
